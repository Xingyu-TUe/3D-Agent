# 几何生成与编辑

**定位**：自然语言/模板生成参数化几何，支持 STP 赋参、拖拽改形和基准方向计算。  
**用户价值**：生成的零件可在线改参数、可收藏复用，立柱/底板等焊装几何可快速落地。  
**条目**：去重后 25 条需求/任务，归并为 19 个功能点。

### 2. 几何生成工程落地路径

- **优先级**：P1　**状态**：规划中　**类型**：支撑能力
- **迭代周期**：8月
- **产品/业务**：付星宇
- **关联 PRD**：-

**包含需求与任务**

- [研发任务] 工程落地优化：微调大模型（这个应该不需要）。注：需要较大的大模型api开销，将M级数量的数据集转成<prompt ， coding代码> 的格式。 （规划中）
- [研发任务] 工程落地优化：针对场景和零件类型，中间层描述写skills. 注：分两条路径，需决策
1. 如果用社区版simplecadapi的话：它的优势是可以把建模过程导出成中间格式json, 并翻译成其他cad软件。但是由于协议严格，需要私有化部署e2b sandbox，需要专业后端人员的支持，且沙箱的输入输出要专门设计，让agent感觉就是直接在和常规python解释器在交互，否则性能可能会下降
2. 如果用其他开源api(如build123d): 这些api的缺点就是它们没有定义一种保存建模序列的中间层导出格式，只有保存几何形态的中间格式(stp)。我们需要评估，我们需不需要转成其他工业软件格式，还是说云端零件能可编辑、云端零件参数能和前端联动就可以了。如果是后者，则其他开源api已经能实现且协议友好。 （规划中）
